# TensorCraft World Model v0

Research branch: a **formal variable ontology plus a low-fidelity, falsifiable combat surrogate** for StarCraft: Brood War. The numerical A-versus-B results are uncalibrated guestimates generated by a toy stochastic model, not measured Pluto matches or predictions from Blizzard's executable.

## Finite-set representation

Let U be the set of 228 legacy unit-type IDs, W the set of 130 weapons, F the 209 movement/Flingy entries, T the 44 technologies, G the 61 upgrades, P the players and M the map cells. Each combat state is a partial assignment over statically typed coordinates and dynamic variables. The important relations are:

- `attacks` ⊆ U × {air, ground} and `uses_weapon` ⊆ U × W
- `morphs_from` ⊆ U × U, `requires_tech` ⊆ U × T and `belongs_to` ⊆ U × R
- `can_observe` ⊆ P × U × Frame with the visibility mask determined by ownership, scouting and detection
- `path_reaches` ⊆ U × M × M × Frame and `counters` ⊆ U × U × Context

At frame t, the hidden physical state S(t) includes locations, health, shields, orders, cooldowns, spores, production, economy and map occupancy. A player's observation O(p,t) is a visibility-filtered projection of S(t). Its actions and the opponent's actions jointly determine the next state through a transition relation. Pluto is an adaptive policy over partial observations. A modification is an explicit intervention in the transition rule, such as setting Devourer top speed to 5.50 px/frame or weapon cooldown to 90 frames.

The registry produced by `python -m starcraft_lab.world_model.ontology registry` enumerates the fields and their evidence sources. `template` emits empty, provenance-aware slots ready to fill. A missing value stays null instead of becoming an assumed zero. Set-algebra queries already distinguish air/ground attackers, detectors, morph relations and tech dependencies.

## Fill the complete numeric stat universe from an owned installation

Extract effective original `arr/units.dat`, `arr/weapons.dat`, and `arr/flingy.dat` from a legally obtained 1.16.1 installation. Optional inputs are `arr/upgrades.dat` and `arr/techdata.dat`. Run privately:

```bash
python -m starcraft_lab.world_model.dat_extract --units /private/units.dat --weapons /private/weapons.dat --flingy /private/flingy.dat --upgrades /private/upgrades.dat --techdata /private/techdata.dat --output /private/full_dat_export.json
python -m starcraft_lab.world_model.calibrate --extracted /private/full_dat_export.json --output /private/local_model_catalog.json
```

The read-only decoder covers 228 units, 130 weapons, 209 Flingy entries, 61 upgrades and 44 technologies. It verifies exact legacy file sizes, links each unit to its movement and weapons entries, decodes source hashes, and preserves the raw fields for later inspection. The overlay copies local scalar stats into named catalog entities while retaining all source checksums. It refuses the research baseline if the input Devourer already differs from 5.00 px/frame or a 100-frame cooldown.

The legacy DAT files do not establish projectile trajectories, simulation order, ability timers, attack animation timings, fog, pathfinding or actual AI policy; the same raw stat can behave differently under context and game engine rules.

## The combat proxy

`combat.py` uses a short 2D stochastic encounter with per-unit positions, movement toward firing range, approximate focus-fire and kiting, per-shot attack cooldowns, HP/shield/armor/size interactions, Mutalisk three-hit bounce, Devourer Acid Spore stacks and limited splash proxies for Corsairs/Valkyries. The spore model applies one bonus damage per stack and increases the affected unit's attack cooldown by 1/8 per stack, up to nine. Short-combat spore decay timing, target selection, attack animation and area geometry are model priors.

The unit attack is modeled approximately as:

````text
effective_hp_damage = multiplier(damage_type,target_size) * max(0.5, raw_hit - armor) + acid_spore_stacks
effective_cooldown = base_cooldown * (1 + acid_spore_stacks/8)
````

Shields first absorb raw damage, with size multipliers applied on the remaining HP hit. Actual Brood War uses fixed-point damage ordering, animation constraints and extra minimum-damage rules. The approximation should be calibrated before any competitive claims.

The encounter outcome is compared using remaining weighted army value, with gas given a configurable shadow price. Tech-building sunk costs, morph downtime, route geometry and investment timing are explicitly excluded from the first-pass score. The four Devourer variants are **control (5.00,100), speed-only (5.50,100), cooldown-only (5.00,90), combined (5.50,90)**. Movement changes for any other unit remain disabled.

## Special sauce: synergy, interventions and active experiment design

**Acid-spore amplification:** The simulator separates spore-induced damage and additional enemy cooldown frames. It runs a spore ablation with otherwise comparable settings to study the mechanism rather than counting Devourer direct DPS alone.

**Four-way causal factorial:** For any predicted score Y(control)=C, Y(speed)=S, Y(cooldown)=D, Y(combined)=B, compute:

- Speed main effect = ((S-C)+(B-D))/2
- Cooldown main effect = ((D-C)+(B-S))/2
- Interaction = B-S-D+C

A positive interaction is the model's claim that speed and cadence support one another beyond their separate contributions. The claim can be tested by actual Pluto matches and direct micro scenarios.

**Disagreement mining:** Each scenario is rerun under sparse/well-microed and clustered/high-focus priors. The model ranks follow-up experiments using proximity to its decision boundary, sensitivity to micro assumptions, factorial interaction and an Acid Spore ablation signal. This is a value-of-information heuristic, not an optimized statistical acquisition function.

## Calibrating against Pluto and live game state

1. Collect actual shot frames and Devourer travel traces under the control and four-arm stat-mod variants. Validate cooldown, projectile hit timing, splash radius, spores and decay before using the surrogate for tactical judgments.
2. Use real replay build orders and economic state to estimate when a Greater Spire and morphing Devourer could exist, and how much Muta production is displaced.
3. Run matched Pluto tests with frozen bandit state and trace identity. Calibrate model policy priors (focus, kiting and formation spread) against observed order/position trajectories.
4. Compare held-out matchup predictions with referee-confirmed outcomes, score calibration error and retain all falsifying cases rather than retrofitting the scenario after the outcome.

Until those measurements exist, any percentages reported by this program are **frequencies inside its imaginary combat model**, useful for prioritizing experiments and learning where the approximations break.

## Fillable research tables and complete named-unit matchup matrix

Create a fresh, empty workspace of provenance-aware CSV and JSON tables:

```bash
python -m starcraft_lab.world_model.scaffold --output-dir /private/starcraft_fill
python -m starcraft_lab.world_model.matchups --json /private/named_unit_matrix.json --csv /private/named_unit_matrix.csv
```

The scaffold has 228 unit rows, 130 weapon rows, a variable registry, the known seed relation graph and 32 blank experiment-arm rows across eight scenarios. Of the 228 unit IDs, a small public subset has explicitly sourced seed values; other fields stay empty until owned-game DAT data or confirmed observations fill them.

The named-unit matrix covers every ordered pair among the seeded units (18 × 18 = 324 capability comparisons). Each cell records whether a direct weapon can hit the target, nominal damage against size/armor, idealized time-to-kill, weighted resource cost and an explicitly uncertain two-sided exchange heuristic. Carrier/interceptor and siege-mode interactions remain excluded. This pairwise table is a **coverage inventory**, not an exhaustive full-game tactical model.

CI attaches these CSV and JSON files to the modeling PR's workflow artifact. They are suitable as editable data/agent targets without copying copyrighted game archives.
